# 发行与外部验收

当前为 0.3.0-rc.3，处于预发行阶段。本文件说明可复现步骤，不代表所有外部步骤已经执行。

## Windows

1. npm ci、npm test、npm run build。
2. npm run package:win 生成 x64 便携版。无凭据时是未签名候选包。
3. 设置 CABLEWISE_TEST_EXE 为打包后 release/win-unpacked/Cablewise.exe 的绝对路径，执行 tests/catalog-smoke.cjs、tests/recovery-smoke.cjs 和 tests/compatibility-smoke.cjs。兼容性用例默认模拟 IPC；恢复用例只修改隔离的测试清单。
4. node scripts/verify-windows-package.cjs 检查版本、原生脚本内容、诊断资料排除，并生成 SHA-256。
5. 由操作人在实机上发起兼容性检查，处理 UAC；验证自动恢复和恢复记录。使用至少一台支持线材属性读取的电脑核对已知规格的实物线，记录单端、双端和多线结果。
6. 正式签名后重新计算发行散列，并对最终签名文件复验。确定下载渠道后发布，下载回验散列与签名。

签名需要发行方的有效证书或代码签名服务配置；不得把证书私钥、口令写进仓库或聊天。当前候选配置明确关闭签名，正式构建时须启用 win.signExecutable 并启用 forceCodeSigning，让缺少证书的构建直接失败。当前尚无签名凭据；发布位置已确定为 GitHub Releases。

## macOS

在带有已知规格线材的物理 Mac 上运行：

    npm ci
    node scripts/verify-mac.cjs
    npm run package:mac

verify-mac.cjs 验证应用流程并生成 test-results/mac-validation.json。零条芯片记录会标为 not-observed，不能据此认为自动读取功能通过。报告不包含设备序列号，仍需核对实物、拔插、单端与多端情况。

分别验收 Apple Silicon 和 Intel 包；将当前 mac.identity=null 的候选配置替换为发行方 Developer ID，启用强制签名并配置 Apple 公证后，在另一台 Mac 完成系统正常打开、扫描和档案恢复测试。当前缺少 Mac 实机与 Apple 发行凭据，此项未执行。

## 发行内容

交付应用、版本说明、散列、适用平台与已知读取限制。work/、test-results/、本地设备标识和第三方微软诊断工具不进入发行包。用户线材档案通过应用 JSON 备份迁移，不随应用更新覆盖。

项目所有者于 2026-11-07 指定创建 GitHub 公开仓库，地址为 https://github.com/code-lawyer/check-your-lines，下载渠道为该仓库的 Releases。候选包使用 Pre-release 标记；正式签名和硬件验收完成前，不发布为正式稳定版。

仓库的 Verify desktop candidates 工作流在 Windows x64、macOS arm64 / x64 上运行锁定依赖安装、单元测试、生产构建、未签名打包和隔离档案操作。只读仓库权限，无发布密钥，不触发管理员诊断；成功包作为 CI 产物保留 14 天。CI 不代表 USB-C 实物读取、签名或公证验收。
